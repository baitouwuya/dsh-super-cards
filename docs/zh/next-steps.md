# 自动下一步

> 属于 [超级卡片](../../README.md) · [文档索引](../README.md)

回合末尾的「下一步」卡有两种来源：模型自己用 `place: "tail"` 写，或者由 Host 在回合结束后自动
生成。前者是默认路径、零额外调用；后者是可选能力，默认关闭。生成逻辑在
[lib/next-steps.js](../../lib/next-steps.js)。

## 开启方式

设置页或插件页把「自动下一步」打开，或手写行配置：

```yaml
config:
  nextSteps: true
  nextStepsMax: 3
  nextStepsTimeoutMs: 15000
  nextStepsMinChars: 200
  # nextStepsProvider: some-provider
  # nextStepsModel: some-model
```

只有显式写 `nextSteps: true` 才开启，缺省或写非布尔值都视为关闭。

## 生成流程

1. Host 监听 `session/event`，在 `turn/end` 后取该回合编号。
2. 从会话日志里收集这一回合所有 `assistant/message` 的文本块，只取用户读到的正文。
3. 解析路由：显式配置的 provider 与 model 成对优先；否则用会话请求头里的 provider 与 model。
4. 发一次很小的模型请求，要求只返回一个 JSON 对象；输入回答最多 6000 字符，超出截断。
5. 防御式解析 JSON：容忍代码围栏与前后说明，裸选项数组也接受，去重并截断字段。
6. 追加一条 `super-cards/next-steps` 会话事件：`{turn, summary?, text, options, at}`。
7. Client 把它渲染在 `tail` 位置：可选简述、一句问题、一排按钮，第一个选项是主按钮。

## 生成契约

| 字段 | 约束 |
| --- | --- |
| `summary` | 可选，1 到 2 句，最多 240 字符；空或不可用时整个字段省略 |
| `text` | 一句问题，最多 160 字符 |
| `options` | 2 到 `nextStepsMax` 个；`label` 最多 40 字符，`prompt` 最多 400 字符 |
| 语言 | 与回答正文同语言 |
| 可用性 | `prompt` 必须能独立作为用户的下一条消息；重复选项被丢弃 |

等价的 JSON 形状：

```jsonc
{
  "summary": "一句话概括这一回合做了什么。",
  "text": "接下来想做什么？",
  "options": [
    {"label": "跑测试", "prompt": "跑一遍这个仓库的测试套件。"},
    {"label": "看 diff", "prompt": "把这次改动总结成 diff。"}
  ]
}
```

模型输出不可用（没有可解析 JSON、没有任何可用选项）时，不追加事件，也不生成空卡片。

## 跳过条件

满足任一条件就不生成，避免无意义调用和重复卡片：

- 未显式开启 `nextSteps`。
- 回答文本短于 `nextStepsMinChars`，避免寒暄也弹卡片。
- 该回合已经有模型手写的 `tail` 卡。
- 该回合已经生成过下一步事件；该判断读会话日志，重放或重复注册都不会追加第二次。
- 解析不到模型路由（既没有显式配置，也没有会话请求头）。
- 当前环境没有可用的 `llm` 服务。
- 当前会话是子代理会话：`header.origin === 'subagent'`、存在 `parentSession`，或
  `delegationDepth > 0`。子代理每一步都会结束回合，在那里生成既无用也浪费调用。

## 超时、并发与取消

- 每次生成带 `nextStepsTimeoutMs` 超时（默认 15000 毫秒），到点中止请求。
- 同一会话同时只运行一次生成；新的生成不会叠加。
- 生成期间用户发出下一轮（`turn/start`）时，本次生成被取消。
- 插件卸载时中止全部在途请求。
- 超时、provider 报错、输出不可用都只导致本次跳过，不会写入错误事件。

## 成本与优先级

- 默认关闭：关闭时调度在扫描日志之前就返回，每个回合的额外成本为零。
- 开启后：每个满足条件的回合产生一次小模型调用，输出上限 800 tokens，输入最多 6000 字符。
- 优先级：模型自己写的 `tail` 卡永远优先。同一回合两者互斥，模型写了就不再生成。
- 瞬态：用户开始下一轮后，上一回合的「下一步」卡（无论手写还是生成）都不再显示；回收看板得到
  的回传卡除外。

## 两种做法对比

| 维度 | 模型手写 tail | Host 自动生成 |
| --- | --- | --- |
| 默认状态 | 开启，模型自己决定 | 关闭，需显式打开 |
| 额外成本 | 无额外调用 | 每个合格回合一次小调用 |
| 可控性 | 内容与措辞由模型当场决定 | 由提示词保证结构，内容来自小模型 |
| 适用场景 | 上下文复杂、需要结合具体结论 | 希望每回合稳定出现收尾建议 |
