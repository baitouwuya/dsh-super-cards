# 排错

> 属于 [超级卡片](../../README.md) · [文档索引](../README.md)

卡片是会话日志的纯函数，多数问题出在客户端模块没加载、配置没生效或内容被归一化丢弃。下面按现象
给出检查顺序。

## 重启后历史卡片不显示

卡片按会话日志里的调用参数重建，数据不会丢。某次冷启动后历史卡片整段消失，通常是客户端模块在
Conversation 服务之前激活，行定义没有注册上。

- 先刷新页面一次，让 Client 半重新加载；历史卡片会按日志重新渲染。
- 若仍然没有，检查 Cordis Inspector 的 `tool.call.toolview` 槽位是否存在 `render_ui` 的占用者，
  以及 Loader 里是否还有 `super-cards` 行。
- 行被禁用或插件被移除时，卡片自然不再显示；重新启用后刷新页面即可恢复。

## 模型说调用成功却看不到卡片

先确认这次调用是怎么发生的：

- 模型在 `run_code` 脚本里调用 `tools.render_ui` 时，会话日志里没有顶层 `tool/call`，只有
  `tool/ptc-dispatch-start` 与 `tool/ptc-dispatch`。行定义同时匹配这三种事件，同一次调用只生成
  一行，结算事件只刷新参数、不新增卡片。
- 在应用自带的 `app.asar` 里搜 `render_ui` 得到 0 次，不代表没有渲染器：渲染器是本地插件，本来就
  不在应用包里。判断有没有加载，看 `tool.call.toolview` 的占用列表。
- 卡片渲染失败时，错误边界会显示「UI 渲染失败」的兜底卡，而不是把对话行弄空；把控制台报错和截图
  一起反馈即可定位。
- 工具调用返回错误时，那一行会显示小型错误卡；错误文字就是 `render_ui:` 开头的原因。
- 卡片位置只显示一条「卡片生成失败」而不是内容时，看notice里的措辞区分原因：**没有携带参数**——这次调用压根没带 `arguments`（常见于直接调用 `render_ui`、而当前模式只允许从 `run_code` 里调用，调用在派发前就被拒绝）；**不是合法的 JSON**——参数被截断或写坏了，下面会附解析器原话；**没有可渲染的区块**——JSON 合法但里面没有 `blocks` 或 `content`。

## 区块被丢弃或类型不认识

`render_ui` 的返回带 `dropped` 数组，每项是 `{index, type, reason}`，按原因处理：

- `unknown block type`：类型名不在 29 种规范类型里。用 `render_ui_blocks` 查正确名字与字段。
- `no usable content`：字段缺失或为空，归一化后不可渲染；补齐必填字段。
- `block type not enabled by config`：该类型被行配置的 `blocks` 关闭；要使用它就把它加回列表。
- `over the block cap`：超过单卡上限；拆成多张卡片。
- `not allowed in a dock board`：看板只接受白名单里的块，改用 `answer` 或换块。

常见误用是把 `content` 的字段名当成区块类型写，例如 `{"type":"note"}`。两端归一化会把它折叠到
渲染同样内容的区块上，只改名字不改数据形状；数据不符合目标区块字段时仍会被丢弃。规范类型只有
29 种，`note`、`summary`、`metrics` 这类名字不在工具枚举里。

## 配置不生效

- 保存配置后该行会重挂一次，工具与提示词随之重新注册；改动应在新一次调用中生效。
- 插件页只显示四项基础配置；选项数、超时、最小长度、生成路由与启用块类型在设置页的完整表单里。
- 手写 YAML 时，未声明的键会让校验失败并报出键名；数值越界会被夹到边界，非法值回退默认。
- `blocks` 写空数组或不写都表示「全部启用」，不是「全部禁用」；想禁用某个类型就列出其余类型。
- `nextSteps` 只认显式的 `true`，`false`、缺省或字符串都不开启。
- 设置页在缺少 `configForms` 客户端服务时只显示一行提示；此时用插件页或手写 YAML 修改。

## 自动下一步不出卡

按跳过条件逐条检查：

- 是否显式配置 `nextSteps: true`。默认关闭，不写就不生成。
- 回答是否短于 `nextStepsMinChars`，短回答不生成。
- 该回合是否已经有模型手写的 `tail` 卡；有就不再生成。
- 该回合是否已经生成过事件；读日志判断，重放不会重复追加。
- 是否解析不到模型路由，或当前环境没有可用的 `llm` 服务。
- 当前会话是否是子代理会话（`origin` 为 `subagent`、有 `parentSession` 或 `delegationDepth > 0`）。
- 是否超时：调大 `nextStepsTimeoutMs` 后重试，并确认会话日志里有没有 `super-cards/next-steps` 事件。
- 手写 `tail` 卡与生成卡互斥；用户开始下一轮后上一回合的卡不再显示，这也是正常行为。

## html 卡片空白

- iframe 的 CSP 禁止一切外部请求：远程字体、脚本、图片都加载不到。改用内联 CSS、内联 SVG 或
  `data:` URI。
- 用卡片右上角的源码视图确认实际运行的 HTML 就是预期内容；Host 会把源码截断到 20000 字符。
- `height` 夹在 120 到 800，内容超出在 iframe 内滚动；高度太小可能只看到空白。
- `html` 不进看板，放在 `place: "dock"` 的卡片里会被丢弃。
- 系统「减少动态效果」开启时，iframe 里的 CSS 动画与过渡被关闭，这是预期行为。

## 样式问题

- 颜色与边框只用 `--dsw-alias-*` 主题 token，明暗主题自动切换；卡片里没有写死的主题色。
- 卡片变窄时 `columns` 自动折回单列，宽表格在卡片内部横向滚动，不是页面级滚动。
- 密度由 `look` 或卡片形状自动决定；想要更紧凑或更宽松时显式传 `look`。
- 系统「减少动态效果」开启时入场、呼吸、进度与图表动画全部关闭，只保留瞬时状态切换。
- 纯静态展示卡没有关闭按钮，这是设计行为；只有带生命周期状态或含 `controls`、`actions`、`live`
  的卡片才可关闭。
- 样式完全不生效时，先确认 Client 半已加载：刷新页面，并检查 `super-cards` 行处于启用状态。
