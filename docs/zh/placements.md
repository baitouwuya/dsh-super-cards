# 四种落位

> 属于 [超级卡片](../../README.md) · [文档索引](../README.md)

`render_ui` 的 `place` 决定卡片挂在会话的哪个位置。四个取值分别对应 Client 半 `PLACEMENTS`
注册表里的四个条目，未知取值回退到 `answer`。默认值可以用行配置的 `defaultPlace` 修改。

## answer

- 默认落位，属于回答正文：卡片插在模型调用它的位置，前面可以写引导段落，后面可以继续写正文。
- 折叠「过程」后卡片仍然可见，因为它位于 `turn` 组树而不是过程里。
- 一张回答里可以多次调用，按调用顺序插入多张卡片。

## process

- 属于执行过程的展示卡，跟着「过程」一起折叠，收起过程就看不到。
- 适合运行中的临时统计、阶段性进度这类只服务过程的信息。
- 工具行本身在过程里不重复显示卡片内容，展开和收起「过程」时呈现一致。

## dock

看板固定在输入框上方、与输入框同宽，是执行期的紧凑状态区。

- 默认只有一行可折叠的状态条：标题、项数、展开箭头；展开后是紧凑内容，高度有上限。
- 看板绑定在自己所属的回合上，回合结束即关闭；关闭后变成一行「看板已关闭」，点击可重新打开。
- 如果模型没有在该回合另外输出答案卡，插件会在回合末尾把看板内容回传成一张普通卡片，见下文。
- 看板只渲染白名单里的块，且最多 4 块：
  `text`、`heading`、`callout`、`stats`、`list`、`badges`、`progress`、`live`。
  其他类型会被丢弃并在结果里报告 `not allowed in a dock board`；超过 4 块时只渲染前 4 块；如果所有
  块都不合格，工具会报错并建议改用 `answer`。
- `live` 块只在看板里生效：它跟随会话自动刷新消息数、工具调用数或最近消息流，不需要模型再次调用。

## tail

收尾卡固定落在这一回合的最后：回答正文之后、底部操作行（复制、重试那排）之前，因此它是用户最后
读到的东西。

- 典型写法是一句问题加一个 `actions` 块：2 到 3 个选项，第一个用 `"tone":"primary"` 做主按钮。
- 同一回合最多显示 4 张 `tail` 卡，按调用顺序堆叠；更早的留在会话日志里但不显示。
- 它是**瞬态**提示：用户一旦开始下一轮对话，上一回合的 `tail` 卡就不再显示。
- `tail` 卡不占回答正文的位置，也不会被当成「模型已经输出了答案卡」而阻止看板的收尾转换。
- 自动生成的下一步卡也渲染在 `tail` 位置；模型自己写过 `tail` 卡时以模型的为准，不再生成。

```jsonc
{
  "place": "tail",
  "look": "relaxed",
  "blocks": [
    {"type": "text", "text": "要我跑一遍测试套件来支撑这次静态审查吗？"},
    {"type": "actions", "items": [
      {"label": "跑测试", "prompt": "跑一遍这个仓库的测试套件。", "tone": "primary"},
      {"label": "先不用", "prompt": "先不用了。"}
    ]}
  ]
}
```

## 弃用看板回传卡

看板在回合结束时关闭并被回收，但信息不丢：如果该回合没有模型自己输出的 `answer` 卡，插件会把
看板内容转换成一张普通卡片，放在回答下方。

- 回传卡是**长生命周期**的，不随下一轮对话消失，因为它用来把看板信息交还给读者。
- 回传卡里的看板状态不再显示「进行中」，而是按结束态渲染。
- 这就是 `tail` 瞬态规则的唯一例外：回传卡保留当时的内容。
- 实现上，回合尾有两个槽位条目：回传卡在前，`tail` 卡栈在后。

## 选择建议

| 需求 | 落位 |
| --- | --- |
| 最终答案、对比、规格 | `answer` |
| 解释执行过程的中间结果 | `process` |
| 运行期进度与状态一览 | `dock` |
| 收尾提问与下一步按钮 | `tail` |
